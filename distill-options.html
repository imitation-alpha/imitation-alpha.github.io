Plan, Define, Act

A simple three-phase loop for keeping multi-step LLM coding tasks tractable, debuggable, and able to recover from being wrong.

Arthur Yau ML Engineer · Independent

Contents

  1. 1 · Plan
  2. 2 · Define
  3. 3 · Act

Most LLM coding agents fail in one of three predictable ways. This article describes a simple workflow — Plan, Define, Act — that addresses all three by separating intent, completion criteria, and execution.

Plan

Before any tool call, the agent writes a discrete-step plan with explicit inputs and outputs. The point isn't to be exhaustive; it's to make wrong assumptions visible before they cost a tool round.

In practice, even a 5-line plan catches roughly half of the cases where the agent would have gone the wrong direction. A good plan is one a colleague could read in 30 seconds and tell you which step is wrong. That's the bar — not "complete" but "falsifiable". 

# PLAN
1. Locate auth middleware
2. Add requireRole('admin')
3. Update tests

Define

The hidden failure mode is "I finished" without a clear definition of done. The Define phase forces the agent to write down what artifacts will exist, what signal indicates success, and what rollback looks like.
