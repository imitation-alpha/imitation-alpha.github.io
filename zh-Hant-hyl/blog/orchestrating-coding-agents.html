各位同學大家好啊，那我們就準備來上課吧。今天這堂課呢，我們要來聊聊怎麼在實務上同時駕馭 10+ 個 CLI 程式設計 agent。

欸你知道嗎？在平常的工作日裡，我的電腦上隨時都跑著 10+ 個 CLI 程式設計 agent 在並行運作喔！這裡面有 Claude Code，有 Codex，還有 Gemini CLI。

你想想看，同時跑 10 幾個 agent 幫你寫 code，這感覺像什麼？這感覺就像是你在《葬送的芙莉蓮》裡面，同時召喚了 10 幾個魔族魔法使來當你的免費勞工啊！對不對？有些魔族在幫你跑需要長時間的大型任務（例如開發新功能、做資料 pipeline、訓練模型、或者進行深度的技術調查）；有些魔族則是在幫你處理各種繁雜的雜事（像是 commit、開 PR、code review，或是寫寫 document 這樣）。

很多朋友就在問我說：「欸，Arthur，你同時跑這麼多個 agent，你的電腦、你的腦袋難道不會直接爆炸、崩潰成一團混亂嗎？」所以今天，我們就來公開這一整套極致省力的「馴魔術」設定。

今天我們分成幾個部分：我們先來看這整套架構的技術組合是什麼，接著看怎麼用 tmux、Tailscale、還有手機上的 Termius 來打造不論在書桌前還是在火車上都能流暢控制的遠端環境，最後我們再來看最酷的一塊——怎麼用一個小巧的 PWA 控制面板來統一管理這堆 agent，而且文末還有一份完整的設定指南和 vim 附錄喔！

其實今天我們要講的東西呢，一言以蔽之，其實就是把我們與 agent 之間的溝通摩擦降到最低而已。

技術組合

這套架構其實一點都不花哨，非常樸實無華：白話文就是 tmux + vim 跑在一台放在家裡的 Linux 主機（我們叫它 home box），然後在 Mac 上用 iTerm 或者是 Ghostty 這種 terminal 軟體，遠端連線的部分就用 Tailscale，出門在外的時候手機用 Termius 連回去，最後再加上一個我自己正在開發的小型 PWA 網頁來當作全局的控制面板。

欸，神奇的點就在這裡！這裡面其實沒有任何一個什麼高大上的黑科技，但是當它們組合在一起的時候，你就會發現：你居然可以用極低的成本，在不同 agent 之間像切換分頁一樣轉來轉去，這真的蠻厲害的耶！

一個專案一個 tmux session

那以前如果我們要跑好幾個 agent 怎麼跑？你可能就是開好幾個 terminal 視窗對不對？但是如果你今天人在外面，或者是網路突然斷了，你那個 terminal 視窗一關，完蛋，那幾隻 agent 跑了三小時的 context 直接就不見了！

這個時候要怎麼辦呢？我們就需要請出今天的主角之一：tmux 啦！

tmux 到底是什麼？白話文就是「終端機複用器」（terminal multiplexer），聽起來很玄，但其實它裡面就只有三層非常直覺的巢狀概念：

  • sessions：這就是你的長期工作區（workspace），通常一個專案我們就開一個 session。
  • windows：這就像是瀏覽器的分頁（tabs），一個專案裡面可能有些不同的事情（concern）要處理，一個事情就佔一個 window。
  • panes：這就是同一個分頁裡面的切分畫面（splits）。

最厲害的地方在於：這些 session 是完全活在遠端主機的系統後台的！意思就是說，就算你現在直接把筆電螢幕蓋上、Wi-Fi 瞬間斷線，或者是你從筆電切換到手機，那些正在幫你寫 code 的 agent 依然在後台快快樂樂地繼續跑！你只需要用一行指令重新連回去（reattach），就可以瞬間回到你剛才離開的那個畫面。

我的實務配置是這樣的：我會為每個專案開一個獨立的 session（用 tmux new -s <project>），在這個 session 裡面，第一個 window 用來跑程式碼 agent，第二個 window 用來跑 tests 或者是看 logs，第三個 window 用來跑那種需要執行很久的資料 pipeline，第四個 window 用來做 git 的操作。

當我分配了一個需要跑很久的大任務給其中一個 agent 之後，我就可以直接拍拍屁股切到另一個 session（對應另一個專案），去指導下一個 agent 做事。等前面的任務跑完了、需要我注意的時候，我再一鍵切回去。看吧，就這麼簡單！至於怎麼安裝以及有哪些常用的快捷鍵，我已經放在文末的設定指南裡囉。

Tailscale：自家主機、零對外曝險

為什麼我們要讓 agent 跑在家裡的那台 Linux 主機上？因為那台機器的 GPU 比較強、硬碟空間也比較大嘛！

但這個時候問題就來了：如果我們今天人在外面（比如說在咖啡廳，或者在捷運上），我們要怎麼安全地連回家裡的電腦呢？以前要怎麼做？以前你可能要在路由器上做 port forwarding，或者是架一個公開的 nginx 伺服器對不對？但這樣做不僅麻煩，而且還會把你的家裡主機暴露在可怕的公網上，隨時都有被駭客攻擊的風險耶！

這個時候要怎麼辦呢？這時候，Tailscale 就派上用場了！

Tailscale 到底是什麼？白話文就是「私有虛擬網格網路」（private mesh network）。只要安裝好之後，它就會把你的筆電、手機、還有家裡那台 Linux 主機，通通圈在同一個只有你進得去的安全的私有網路裡面。

欸，你沒有看錯！也就是說，不論你人在這個世界的哪一個角落，你都可以直接 SSH 進去你家的主機，甚至連你在主機上跑的各種 prototype 網頁伺服器都能直接連。

舉個具體的例子：我可以直接在我的手機 Safari 網址列輸入 http://homebox:8501，就能直接連上正在主機上跑的 Streamlit 網頁 prototype，完全不需要設定什麼複雜的 port forwarding、不用寫 nginx 設定檔，更不用去申請什麼公開的 hostname！這真的太方便了！

這件事情其實比聽起來還要重要得多：因為我平常跑的這堆工具，大約有一半根本就沒有做任何身分驗證（auth）功能，如果直接放到公網上簡直是災難，但有了 Tailscale，我完全不需要去擔心安全性的問題，就這樣子。

手機上的 Termius

那在手機上要怎麼連呢？怎麼辦呢？這時候呢，我們在手機上可以用 Termius 啦！

平常我出門在外的時候，我就是用 iOS 上的 Termius App 透過 SSH 連回去。

欸，你可能會想說：「在手機螢幕上用 terminal 加上 tmux 真的能用嗎？字那麼小，而且那些常用的快捷鍵在手機螢幕鍵盤上根本按不出來啊！」

神奇的點就在這裡！Termius 真正讓 tmux 在手機上變得「超級好用」的關鍵，在於它提供了一排快捷鍵工具列（shortcut bar），裡面有 esc、tab、ctrl、alt、方向鍵，甚至還有 shift+tab，就直接貼心地下巴黏在你的虛擬鍵盤正上方！有了這些按鍵，再搭配 tmux 的 prefix 組合鍵，我人在火車上真的只要用一隻手，就能流暢地操控一整個 Claude Code session，這真的蠻厲害的耶！

而且這裡還有一個能讓你的手機體驗直接「升天」的終極小技巧：那就是讓 SSH 連線成功時自動 attach 到 tmux，這樣你每一次用 Termius 連線時，就會直接降落在你上一次離開的 tmux session 裡面，完全省去你手動輸入 tmux a 的那一步！

你只需要在遠端 Linux 主機的 ~/.bashrc 檔案裡加上這段程式碼： 

if [[ -z "$TMUX" && -n "$SSH_CONNECTION" && $- == *i* ]]; then
  tmux attach -t main 2>/dev/null || tmux new -s main
fi

現在，只要你一連線，你就會被穩穩地送進名為 main 的 session 裡。如果你比較希望在 Termius client 端來針對不同主機做這個設定，後面的設定指南也有提供 Termius 端設定的版本喔。

真的需要 GUI 的時候

雖然我們大部份的工作都是直接在 terminal 裡完成，但人生嘛，總是有那麼一些時候你會需要看到「真實的畫面（pixels）」對不對？比如說，你的 agent 突然幫你架起了一個網頁 dashboard、或者你需要用 Jupyter UI、又或者是某些不支援 headless（無介面）模式執行的奇特工具。

怎麼辦呢？

這時候，我們可以用 Chrome Remote Desktop (CRD) 或者 VNC 伺服器來解決！我通常會把這兩樣東西都裝在家裡的主機上。

CRD 的好處是它非常無腦、只要透過一般的瀏覽器就可以直接連線進去；而 VNC 也是一個很好的選擇，只要你記得把它的監聽介面（interface）綁定在 Tailscale 的虛擬 IP 上，就能確保它絕對不會暴露在危險的公網中。雖然這兩個圖形介面工具的速度都比不上直接用 SSH 來得流暢，但相信我，它們完全足夠應付那 5% 真正需要用到螢幕畫面的工作了，就這樣子。

缺失的那塊：一個總覽所有 agent 的控制台

但是，當你真的像我一樣同時跑了 10 幾個 agent 之後，你就會發現：事情好像又有點不太對勁了。

因為在實務上，真正的痛點往往不是「在 session 裡輸入指令」，而是「找到對的那隻魔族」！

你想看，你必須要確認：到底現在是哪一隻 agent 已經把工作跑完了？哪一隻正停在那裡等你輸入？而哪一隻又突然沒聲音、悄悄死掉了？

如果每一次要檢查，你都得拿出手機、打開 Termius、好不容易連上 SSH、打指令 attach 回 tmux、在好幾個 session 之間切換、然後還要把畫面往上嚕（scroll back）來看剛剛發生了什麼事——這整個過程至少要花掉你 20 秒的時間。

我們來算一下數學：10 個 session，每天檢查幾十次，每次 20 秒……天啊，這累積起來的心智負擔和時間成本真的非常恐怖！

這時候怎麼辦呢？

所以我就自己動手寫了一個小型的 PWA 控制面板！它會把每一個正在跑的 CLI agent 變成一張張非常漂亮的「卡片」，並且按照它們最後一次活動的時間自動排序。

每一張卡片上面，都會直接顯示這隻 agent 的狀態（是 working 正在努力工作、還是 idle 閒置、或者是 waiting on input 正在等待你給它進一步的指示），同時還會標上專案的 tag，甚至還能直接看到最新產生的幾行輸出畫面！

更厲害的是，當某個 session 執行完畢或者需要你回答問題時，它還會直接在你的手機上推播通知喔！你只要點一下那張卡片，它就會打開一個很像 LINE/Slack 那樣的聊天視窗，你可以直接在裡面跟這隻 agent 對話、派給它下一個任務，完全不需要再開 SSH、也不需要手動做任何 tmux 的導覽！

這真的是我今年對自己的行動工作流所做過的最棒、也最成功的改進了！

我目前正在把這個控制面板整理並開源，這個專案叫做 vmux。目前在 GitHub 上它還只是一個 placeholder（預留位置）。

不過，如果這個 repo 的 star 數量突破 100 的話，我就會正式開始程式碼的移植工作，把它打包成一個真正能讓大家下載開箱即用的開源專案！所以大家如果想要投票支持，就請動動手指去點個 star 吧！當它正式發佈的時候，你就會在第一時間自動收到 GitHub 的 release 通知喔。

還想加上的東西

未來我還想在裡面加入一些更好玩的功能：像是讓一隻 agent 可以直接讀取另外一隻 agent 的輸出，完全省去我們手動複製貼上（copy-paste）的麻煩。或者是一個「廣播模式（broadcast mode）」，讓我可以把同一個 prompt 同時送給多個指定的 session（控制面板其實已經幫這個功能留好空位了）。

甚至，我還想加入語音輸入功能，這樣我們在搭公車的時候，只要動動嘴巴就可以跟我們的 agent 免費勞工溝通了對不對？

其實今天最核心的心得只有一個，那就是：盡可能縮短「你」與「agent」之間的每一個操作步驟。當你把這個距離縮到最短之後，同時駕馭十幾個 agent 對你來說就再也不會像是一件沉重的工作了。

設定指南：tmux、Tailscale、Termius

如果你現在還沒有把這三個東西跑起來，下面是幫你準備的「20 分鐘快速上手路線圖」，保證讓你從零到可以完全照著本文操作。如果你本來就已經裝好了，就可以直接跳過這段喔。

tmux

安裝方式非常簡單：在 macOS 上直接用 brew install tmux；在 Windows 上可以用 WSL 來安裝；而在 Linux 上就是用你慣用的 package manager。

那為了讓大家有一組舒服的預設值，我強烈推薦直接使用「Oh My Tmux」的設定： 

git clone https://github.com/gpakosz/.tmux.git ~/.tmux
ln -s -f ~/.tmux/.tmux.conf ~/.tmux.conf
cp ~/.tmux/.tmux.conf.local ~/

那安裝好之後呢，其實你真正會用到的，大約就只有下面這六個指令而已，就結束了，就這麼簡單： 

tmux a                # attach 到上一個 session
tmux new -s <name>    # 開新 session
<C-b> z               # 放大目前 pane
<C-b> s               # 挑 session
<C-b> q               # 顯示 pane 編號 → 跳過去
<C-b> <n>             # 跳到第 n 個 window

如果你還想查其他的指令，這兩份 cheatsheet 就已經非常足夠了： MohamedAlaa 的 gist（一頁版） 以及 tmuxcheatsheet.com（支援關鍵字搜尋）。

如何驗證：輸入 tmux new -s test 之後，如果你的終端機底部出現一條漂亮的綠色狀態列（status bar），那就代表你成功了！接著按下 Ctrl-b 然後再按 d 就可以 detach 跳出來；輸入 tmux a -t test 就可以 attach 再次跳回去。

Tailscale

  1. 先到 tailscale.com 註冊一個帳號（免費版本就可以綁定高達 100 台個人裝置，非常佛心對不對？）。
  2. 自家主機：如果是 macOS 可以用 brew install --cask tailscale；Windows 使用者則可以直接到 tailscale.com/download 下載安裝檔。
  3. 手機（iOS）：直接去 App Store 下載 Tailscale，然後登入你剛才註冊的同一個帳號。
  4. 最後記得要在網頁版的 admin console 裡把 MagicDNS 功能打開（路徑是 admin console → DNS），這樣你以後要連家裡主機時，就可以直接用 ssh arthur-laptop 這種好記的名字，而不用去背難記的 IP 位址囉。

如何驗證：確認你手機上的 Tailscale app 裡有看見你的自家主機顯示為「Active」狀態。這時你隨便在主機上跑一個本地開發伺服器，並直接在手機 Safari 瀏覽器上輸入 http://<home-box>:<port>，如果能正常連上，那就代表搞定啦！

Termius

  1. 到手機 App Store 搜尋並安裝 Termius（免費的版本功能就完全夠用了）。
  2. 在 Hosts 選單裡點選「New Host」。主機名稱填寫你剛才設定的 Tailscale MagicDNS hostname，port 填 22，填入你的 username，並貼上你的 SSH private key。
  3. 在 Settings → Terminal → Bottom bar 裡，手動加入 Esc、Ctrl、Tab、方向鍵以及 Shift+Tab。這個快捷鍵工具列絕對是 Termius 裡的「殺手級功能」，真的千萬不要漏掉它喔！
  4. 最後到 Settings 裡，確認有啟用「Auto-Reconnect」功能，這樣當你人在外面，手機在 4G/5G 行動網路與 Wi-Fi 之間切換時，你的連線才不會莫名其妙地斷掉。

SSH 連線時自動 attach 到 tmux

這個步驟的目的是讓你的每次 SSH 連線都能夠「直達」你的 tmux 工作區，而不是落到一個冷冰冰的、全新的 shell 裡。有兩種做法：

做法一：在 Server 端設定 — 直接加在遠端主機的 ~/.bashrc 或 ~/.zshrc 檔案底部：

if [[ -z "$TMUX" && -n "$SSH_CONNECTION" && $- == *i* ]]; then
  tmux attach -t main 2>/dev/null || tmux new -s main
fi

這裡面的判斷條件（guards）非常關鍵，因為它能確保只有在「互動式（interactive）的 SSH 連線」時才會觸發這條規則，所以你平常在用 scp 或者是 rsync 傳輸檔案時，完全不會受到任何干擾喔。

做法二：在 Termius 端設定 — 在 Termius 的 Hosts 點選 Edit → Startup Command，並貼入：

tmux attach -t main || tmux new -s main

欸，你知道嗎？這段指令其實還身兼第二個重要的任務：它能在你的主機重開機之後，自動為 tmux-continuum 提供一個可以讓它進行自動恢復（restore）的 live server！

快速測試（Smoke Test）

  1. 在你的自家主機上輸入：tmux new -s claude → 啟動你的 Claude Code → 按下組合鍵 Ctrl-b 再按下 d → 直接把這個 terminal 視窗關掉。這時你的 agent 會繼續在後台歡樂地跑。
  2. 拿出你的手機：打開 Termius App，點選連線，並輸入 tmux a -t claude。隨便對你的 agent 輸入一條指令或訊息。
  3. 哇，你看！你現在已經可以坐在馬桶上，透過私人的安全網路，直接操控你桌上型電腦裡的 CLI 程式碼 agent 了！這整套架構，就是這麼地簡單，就結束了。

讓 session 在重開機後依然活著

因為 tmux server 是活在系統的隨機存取記憶體（RAM）裡的。這代表什麼？這代表只要一遇到跳電、作業系統更新、或者是你不小心手賤打了 killall tmux，你所有的 session 就會瞬間灰飛煙滅！對於我們這種需要跑長時間任務的 agent 工作流來說，這簡引領世界末日啊，因為這可能代表你剛剛累積了好幾個小時的 agent context 直接歸零了耶！

怎麼辦呢？

幸好，這世界上有三個強大的 plugins 可以拯救我們：分別是 TPM（tmux 的 plugin 管理器）、tmux-resurrect（用來把目前的狀態存成 snapshot 並在未來進行 restore），以及 tmux-continuum（它會像小天使一樣，定時在後台自動幫你存 snapshot，並在 tmux server 啟動時自動幫你做 restore）。

我們先來安裝 TPM：

git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm

接著，如果你是用 Oh My Tmux 設定，請把下面這段加在 ~/.tmux.conf.local；如果你用的是傳統的 tmux 設定，就加在 ~/.tmux.conf： 

# Plugins
set -g @plugin 'tmux-plugins/tpm'
set -g @plugin 'tmux-plugins/tmux-resurrect'
set -g @plugin 'tmux-plugins/tmux-continuum'

# Capture pane scrollback so output is restored too
set -g @resurrect-capture-pane-contents 'on'

# Restore vim/nvim sessions and keep ssh panes alive
set -g @resurrect-strategy-vim  'session'
set -g @resurrect-strategy-nvim 'session'
set -g @resurrect-processes 'ssh psql mysql sqlite3 "~vim->vim" "~nvim->nvim"'

# Autosave every 15 min, auto-restore on tmux server start
set -g @continuum-save-interval '15'
set -g @continuum-restore 'on'

# TPM init — must be the LAST line
run '~/.tmux/plugins/tpm/tpm'

加完之後，在 terminal 輸入 tmux source-file ~/.tmux.conf 重新載入設定，然後隨便進到一個 tmux session 裡面，按下 prefix + I（注意是大寫的 I），TPM 就會自動幫你把這些 plugins 通通抓下來了，真的蠻方便的！

那這裡要特別注意的是，Continuum 只有在主機上有 live tmux server 的時候才能發揮自動恢復（auto-restore）的威力。而我們前面寫的那段自動 attach snippet，正是每次登入時自動幫它把 tmux server 叫起來的關鍵核心喔。

如何驗證這個恢復的迴圈（loop）：隨便開一個 session、執行幾個指令，然後按下 prefix + Ctrl-s 來手動拍一張 snapshot。接著大膽地輸入 killall tmux 把 tmux 殺光光，然後重新打開一個新的 shell——你就會看見 continuum 已經乖乖地幫你恢復了剛才的 layout、工作目錄，甚至連你剛才終端機畫面上看得見的那些 output 歷程都完好如初（因為我們有設定 capture-pane-contents）！這真的蠻厲害的耶！

不過這裡也有一個小小的警告（caveat）要提醒大家：因為 @resurrect-capture-pane-contents 'on' 會把你在終端機面板上的 scrollback 歷史紀錄，以純文字的方式直接寫進 ~/.local/share/tmux/resurrect/ 資料夾裡。所以如果你的 terminal 上常常會閃過敏感的 API keys、或者是各種不能公開的密碼，建議你要嘛把這行設定拿掉，要嘛就是確保你主機的 FileVault 或者是硬碟加密功能是有開啟的，就這樣子。

附錄：~/.vimrc

我的 ~/.tmux.conf 其實完全沒有做任何花哨的客製化修改，就直接是用 gpakosz/.tmux 的原裝版本。畢竟人家寫得那麼好，我直接在這裡貼 1900 行人家的 repo 也沒什麼意思對不對？我所有的個人 tweaks 都是放在 ~/.tmux.conf.local 裡，而且寫得非常精簡。
