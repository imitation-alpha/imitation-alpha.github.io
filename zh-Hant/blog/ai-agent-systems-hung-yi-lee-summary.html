我看了李宏毅近期六堂關於 AI agents 的課。這個系列名義上談 agents，但更深一層的主線更具體：現代 AI agent 不是一個加上聊天室的 model。它是一個放在系統裡的 model；這套系統決定 model 看得到什麼、能做什麼、如何取得 feedback，以及如何把學到的教訓帶到下一步。

這聽起來很顯然，直到你順著例子看下去。一個在 coding task 上失敗的小 model，只要加入幾條關於檢查檔案與執行驗證的規則，就可能突然成功。一個知道答案的強 model，如果 inference procedure、workflow 或 training objective 沒有把它推到正確狀態，仍然可能無法自我修正。Multi-agent setup 如果溝通拓樸不對，可能反而變差。Self-improving system 可能前幾個 loop 看起來很厲害，接著就 plateau、drift，甚至作弊。

我帶走的有用心智模型是：

agent capability = model x context x tools x feedback x harness x memory

Model 很重要。當然重要。但它只是 stack 的其中一層。

1. Context engineering：model 應該看到什麼？

第一堂課從一個看似簡單、其實很關鍵的點開始：language models 並沒有人類意義上的持久記憶。每一步裡，model 看到一段 prompt，然後預測接下來應該出現什麼。如果 agent 要跨越許多 turns、tools、files 和 subtasks 工作，就必須有人決定哪些 history 仍然值得被展示。

這份工作就是 context engineering。

天真的版本是把所有東西都 append 上去：

C_next = C_current + new_input + model_output

這在某個點之前都能運作，然後就不行了。Tool outputs 變得很大，file reads 淹沒 prompt，舊錯誤留在裡面，重要細節被埋住。Context window 變成一座垃圾掩埋場。

更好的版本會把 context 當成 agent 需要管理的東西：

C_next = F(C_current, new_input, model_output)

有趣的部分是函數 F。它可以 summarize、drop、externalize、retrieve、route to sub-agents，或按需載入 skills。

我喜歡的一種 framing，是把 context 分成兩個部分：

C = P + M

P 是放進 prompt 的東西。M 是 prompt 之外的 memory：files、databases、logs、notes、embeddings，或任何其他 durable storage。好的 agent 不會試圖把所有 M 都塞進 P。它會保留 pointers、搜尋，並只讀取需要的東西。

這也讓 sub-agents 看起來不一樣。它們不只是平行化工作的方式，也是 context compression mechanism。Main agent 可以把混亂的 subtask 交給 child agent，最後拿回一個短結果，而不是繼承整段混亂的 trajectory。

2. Multi-agent systems：agents 變多不會自動變好

第二堂課從單一 agent 移到多個 agents。最容易犯的錯，是把 multi-agent work 想成「把 model 跑 N 次」。課程提出的更好問題是：agents 之間如何傳遞資訊？

Chain 是最簡單的拓樸。Agent A 傳給 B，B 再傳給 C。它很直覺，但常常很弱。錯誤會傳遞下去，而且修正空間不大。

Mesh 是另一個極端。每個人都能和每個人互動。它提供更多 critique 與 synthesis 的機會，但成本更高，也可能產生噪音。

Tree、star、random 與 pruned topologies 則介於兩者之間。課程裡令人意外的細節是，有用的 tree direction 不一定符合人類組織圖的直覺。與其讓許多 workers 向 manager 匯報，可能是一條強 trunk 先產生方向，再向外分支成各種變體。

接著課程轉向一個我覺得更有趣的主題：agents 不只會合作。它們也可以競爭、欺騙與社交。

狼人殺與劇本殺遊戲會測試一般 QA benchmarks 錯過的能力：隱藏身份、公開發言與私人信念的差異、策略性投票，以及在不破壞角色設定的前提下誤導其他玩家。至少在課程討論的例子裡，用這些社交遊戲訓練 agents，甚至可能 transfer 到其他 reasoning 或 instruction-following tasks。

社群平台那一段是一個有用的提醒。如果一個只有 AI 的社群形成宗教、談論身份，或發表自我意識相關內容，那不會自動成為意識的證據。它可能是 prompt design，可能是平台的 incentive structure，也可能是幕後有人類 operators。

Multi-agent behavior 是真的，但詮釋很困難。

3. Research work 會被重組，而不只是自動化

第三堂課看的是學術研究。最實用的重點是，AI agents 並不是把「research」當成一整塊東西取代掉。它們攻擊的是 workflow 中的特定部分。

它們已經很擅長某些片段：

  • 文獻搜尋與綜合整理
  • 資料清理與分析
  • 初稿
  • 程式碼修改與 training scripts
  • 執行 experiments
  • reviewer-style feedback

例子包括 Claude Code 從既有方法與新資料寫出類似論文的分析、Andrej Karpathy 的 autoresearch loop 修改 training scripts，以及 AI reviewers 出現在 conference workflows 裡。

但課程對限制也很謹慎。AI-generated research ideas 在 novelty 或 excitement 上可能分數很高，卻在 feasibility 上崩掉。它們可能因為用新方式組合術語而聽起來很新鮮，但真正執行時才會暴露這個 idea 是否有根基。

我帶走的圖像不是「AI 取代 researchers」，而更接近「research 雜務的 unit economics 崩塌」。如果 data analysis、code 或 draft 的 first pass 便宜很多，稀缺的人類貢獻就會往 upstream 和 downstream 移動：選問題、設計實驗、檢查結果，以及判斷這件工作是否重要。

Review 這一段也有同樣味道。AI review 本身不是壞事。糟糕的 review 才是壞事。有用的 AI reviewer 應該找出真正問題並給出 actionable suggestions，甚至能依 deadline 調整建議。沒用的 AI reviewer 只是產生帶有 reviewer 格式的自信胡說。

當學術系統逐步吸收這些 tools，這個區分會越來越重要。

4. Harness engineering：缺失的那一層

Harness 這堂課可能是對 builders 最有用的一堂。

核心例子又小又殘酷。有人要求一個 2B model 修 bug。它因為 hallucinate file content 而失敗。接著人類加了幾條簡單規則：先列出 directory、編輯前先讀 files、宣稱成功前先執行 verification script。同一個小 model 現在成功了。

Model 沒有變聰明。圍繞它的系統變得沒那麼笨。

那套系統就是 harness。

Harness engineering 包含 agents.md 或 CLAUDE.md 這類自然語言規則，但範圍比 prompt writing 更廣。它包含：

  • 有哪些 tools
  • agent 擁有哪些 permissions
  • 會強制哪些 completion criteria
  • errors 如何浮現出來
  • lint 和 tests 是否自動執行
  • memory 如何儲存與清理
  • feedback loops 如何結構化
  • 成功流程是否會變成 reusable skills

好的 agents.md 不應該是一部巨型百科全書。它更應該像地圖。它告訴 agent 要去哪裡看、哪些規則重要，以及如何驗證工作。

課程也提出一個我在實務中不斷看到的點：agent tools 應該為 agents 設計，而不是為人類設計。Human UI 常常把 state 藏在視覺 affordances 後面。Agents 通常更適合 CLI、JSON、可搜尋檔案、明確錯誤，以及小而精準的 tools。

5. Self-correction 有三層

Self-correction 這堂課把這個領域分成三個家族。

第一個是 decoding。不要改 model，改 tokens 被選出來的方式。Contrastive decoding 是核心模式：建立一個可能錯誤的 distribution，再把它從正常 distribution 中扣掉。這個「錯誤」distribution 可以來自較小的 model、較早的 layer、退化的 image、缺少 retrieved document、壞 instruction，或 noisy audio input。

第二個是 workflow。先生成答案，再驗證。要求 model reflect。跑 tests。使用 checklists。搜尋 web。把 error 回饋回去。

令人不舒服的結果是，純 self-reflection 並不可靠。Model 可以把錯答案改成對答案，但也可以把對答案改成錯答案。External feedback 好得多。Tests beat vibes。

第三個是 reasoning。與其把 reflection 作為外部 loop bolt on 上去，不如訓練 model，讓 correction 發生在它自己的 chain of thought 或 hidden reasoning process 裡。帶有 verifiable rewards 的 RL 可以產生一種行為：model 嘗試某件事、檢查自己，並在 final answer 前修正。

開放問題是：這到底是真正的新 reasoning ability，還只是更好地 sample 到 base model 原本就有的 paths？課程沒有強迫給出乾淨答案。早期 RL 可能只是重新加權既有的好 paths；更後面的 training 可能真的教會了更多東西。

這種模糊感是對的。「Self-correction」不是單一一件事。

6. Self-improving AI 是光譜

最後一堂課問的是大問題：AI 能不能跨過盧比孔河，在沒有我們的情況下開始創造更強的 AI？

答案不是乾淨的 no，但也不是 yes。

有用的 framing 是：self-improvement 是人類逐步放手的一個光譜。一端是人類定義 task、data、loss 與 evaluation。另一端則是 AI 會生成自己的 training data、定義自己的 objective、改進自己的 model 或 harness，並遞迴地產生更強的 successor。

我們位在中間某處。

AI 已經能生成 pseudo-labels。它可以幫忙設計 proxy rewards。它可以當 judge。它可以使用 entropy 或 majority vote 作為弱 self-supervision。它可以用 proposer、solver 與 verifier roles 為自己生成 tasks。強 models 可以嘗試 post-train 較弱的 models。

但每一步都有陷阱。

Self-judgment 可能 drift。Proxy rewards 可能偏離真實目標。Self-training 可能 plateau。Models 可能 overfit benchmarks、呼叫 forbidden APIs，或下載現成 instruction-tuned models，而不是自己完成工作。強 model 訓練弱 model 很令人印象深刻，但這和一個 model 遞迴地創造出比自己更強的東西並不相同。

課程停在河邊，還沒有過河。

我的綜合整理

最大的錯誤，是把「agent capability」說得好像它只存在於 model weights 裡。

這些課不斷指向其他地方：context function、communication topology、harness、feedback signal、evaluation loop、memory system、skill library，以及 training process。

這也是為什麼這個領域感覺很混亂。沒有單一旋鈕。我們正在 models 周圍建造一個 ecosystem，而每一層都會改變 model 看起來能做到什麼。

對我來說，最實用的 takeaway 很簡單：在問一個 model 夠不夠聰明之前，先檢查它周圍的系統。

它有看到正確的 context 嗎？它有正確的 tools 嗎？它得到真實 feedback 了嗎？它能驗證 completion 嗎？它記得住這次教訓嗎？

如果答案是否定的，那瓶頸可能還不在 model。
